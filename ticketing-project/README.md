# IT Support Ticketing Project

I created this small ticketing project to practise how IT support issues could be recorded, categorised, prioritised and resolved.

The tickets are fictional examples based on common first-line IT support scenarios.

## What I Practised

- Recording support issues
- Categorising tickets
- Assigning priorities
- Considering user impact
- Recording troubleshooting steps
- Documenting resolutions
- Knowing when an issue may need escalation

## Ticket Categories

The example tickets cover areas such as:

- Network
- Hardware
- Software
- Accounts
- Access
- Performance

## How I Would Triage a Ticket

When a new ticket comes in, I would first understand what the user is experiencing and how many people are affected.

I would then consider:

1. What is the problem?
2. Who is affected?
3. When did it start?
4. Is there an error message?
5. What has already been tried?
6. How much is the issue affecting the user or business?
7. Can I resolve it using the support procedures available to me?
8. Does it need to be escalated?

## Priority

I would not decide priority based only on how urgent the user says the issue is.

I would consider the impact and urgency of the problem.

For example, an issue affecting several users may need more attention than the same issue affecting one person.

## Example

**INC005 – Several users cannot access shared files**

This was given a high priority because multiple users are affected.

I would first check whether the problem is caused by the network, the shared folder, permissions or the server.

If the issue could not be resolved within my level of access or support procedures, I would document the checks I had completed and escalate it to the appropriate team.

## What I Learned

This project helped me practise thinking about support issues from the user's point of view rather than only focusing on the technical problem.

Good ticket documentation should make it clear:

- What happened
- Who was affected
- What was checked
- What was done
- Whether the issue was resolved
- Whether further action is needed
