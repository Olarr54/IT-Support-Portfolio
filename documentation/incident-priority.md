# Incident Priority

## Purpose

IT support teams need to prioritise incidents so that issues affecting users and business operations are handled appropriately.

## Factors Considered

Two important factors are:

### Impact

How many users or systems are affected?

Examples:

- One user
- Several users
- Entire department
- Organisation-wide

### Urgency

How quickly does the issue need to be resolved?

Examples:

- Minor inconvenience
- User unable to complete an important task
- Critical business system unavailable

## Example

### Low Impact / Low Urgency

One user has a minor application issue.

### High Impact / High Urgency

A critical system is unavailable to a large number of users.

This would normally require much faster attention.

## Important Principle

I would follow the organisation's own incident priority matrix and service-level procedures rather than deciding priority entirely on my own.
